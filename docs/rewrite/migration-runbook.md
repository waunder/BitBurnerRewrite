# Rewrite migration runbook (inactive skeleton)

Migration is serialized and starts only after the relevant G2/G3 evidence and
exact authority. Browser proof never grants Steam permission.

1. Inspect/admit the exact environment; unknown identity makes no target write.
2. Verify an immutable inactive release and preserve current reality.
3. Obtain authority and resource ownership; drain/quiesce only proven owned
   predecessors. Preserve foreign and legacy processes/state.
4. Activate through the generation CAS chain, observe boot receipt and
   reconcile an unknown result before repeating anything.
5. Roll back only to retained verified bytes under a new generation and fresh
   authority; never restore/import a save or blindly reverse an irreversible
   effect.

Retire a legacy path only after replacement covers known failure, recovery,
export and state compatibility paths. Keep legacy source/records; do not copy
historic accounting over observed reality.
